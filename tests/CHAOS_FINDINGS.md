# 重ね塗りの探索テスト — 2026-09-29

専用の headless Chrome / WebGPU 上で、アプリと同じ OilEngine の beginStroke / moveStroke / endStroke を呼び出した。ユーザーの Chrome や絵は操作していない。ネイティブ入力の操作感・遅延の評価ではなく、描画結果とエンジン状態の評価。

## 最優先：新しい筆跡が既存の層を突然混ぜる

再現：2 層設定で赤を横に、青を縦に描き、交点に白または同じ青を筆圧 0.001 で単押しする。陰影・流体計算とも OFF。

| 操作 | 交点の RGB（陰影なし） |
|---|---|
| 押す前 | 44, 100, 150 |
| 筆圧 0、白 | 44, 100, 150 |
| 筆圧 0.000001、白（数値上の極限テスト） | 84, 70, 66 |
| 筆圧 0.001、白（ペン入力の下限） | 84, 71, 67 |
| 筆圧 0.001、同じ青 | 83, 70, 66 |
| 3 層設定、筆圧 0.001、白 | 46, 101, 150 |

筆圧 0.000001 では新しい層は約 2.02e-11 m しかないのに、赤 0.303 mm と青 0.318 mm が全量混合される。追加量を 0 に近づけても色の変化が 0 に近づかない。明確な不連続。

原因：src/shaders.js の brush パスで、占有層数が上限の場合、新しいストロークの堆積前に q[0] と q[1] を mixwide で全量統合する。積層の見え方と顔料の混合は等価ではない。微量の堆積でもこの統合が実行される。半径内のセルが順次統合されるので、円形の変色や筆跡の輪郭が現れる。

3 層設定では今回の 3 回目の接触は改善するが、容量上限時の統合処理自体は残る。4 回目の試験でも下層統合を確認したが、その試験では厚い白い上層に隠れて画面上の差は出なかった。「3 層なら解決」とは判断できない。

## 単押しの厚さが筆サイズに依存しすぎる

同じ色・濃度 100%・筆圧 0.75・1 回の単押しの中央厚さ：半径 16 px は 28.13 µm、48 px は 9.54 µm、96 px は 4.79 µm。大筆ほど薄い。

原因：移動中のスタンプを細かくするための距離補正が、初回の単押しにも適用されている。接触開始と移動による堆積を区別していない。物理的な筆の模型がないので厚さの絶対的な正解は断定できないが、現在の逆比例はブラシ素材から導かれたものではなく、補間密度の副作用。

## 目視で残る違和感（調整・モデル評価が必要）

- 白を湿った赤・青にまたがって引いても、色をほぼ引きずらず均一な帯になる。「描く」の pickup 0.001 と強制混合 OFF により、以前の過剰混合を避ける一方、湿った絵具を巻き込む表現が弱い。これは描画結果で確認した傾向であり、すべての実物の油彩条件で不可能という意味ではない。
- 空筆では円形スタンプの輪郭・半透明の移動跡が目立つ。
- 24 回のランダム多色重ね塗りでは、重なった帯や切り抜きのような境界が目立つ。3 秒の流動後は大きくぼける。滑らかさ・色の巻き込み・層統合を別々に評価すべきで、陰影の平滑化だけでは解消しない。

chaos-diagnostic.png の 1〜7 は、サイズ別単押し、微小筆圧の白、交互の色の単押し、白の横断、空筆の横断、24 回ランダム描画、3 秒後。

両ページの `ok` は診断スクリプトが完走し GPU エラーがなかったことを示す。リアリティの合格判定ではない。今回エンジンの修正は行わず、再現ケースと結果を記録した。

修正の優先順は、層数上限で見た目が跳ぶ問題、単押しと移動の堆積の分離、描画時の連続的な色の巻き込み。単純な層数追加や強い混合への巻き戻しでは根治しない。
